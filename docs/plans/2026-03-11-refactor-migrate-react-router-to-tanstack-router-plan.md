# Migrate React Router to TanStack Router

## Overview

Replace React Router v7.5 with TanStack Router in `apps/frontend-react/` to get fully type-safe routing — type-safe paths, search params (Zod-validated), links, and navigation at compile time. Uses file-based routing with the Vite plugin for auto-generated route tree and built-in code splitting.

**Scope:** `apps/frontend-react/` only. No other apps or packages are affected.

## Problem Statement

React Router v7 has limited type safety — paths are strings, search params are `unknown`, and broken `<Link to="/campaings">` (typo) compiles without error. TanStack Router generates a fully typed route tree where every `<Link>`, `useParams()`, `useSearch()` is compile-time checked.

**Why now:** 30 of 32 routes are placeholder pages with no real logic. Only ~16 source files and ~4 test files reference `react-router`. This is the lowest-cost migration window.

## Proposed Solution

Big bang replace — swap React Router for TanStack Router in one pass (see brainstorm: `docs/brainstorms/2026-03-11-tanstack-router-migration-brainstorm.md`). File-based routing with nested directories, `beforeLoad` auth guard, Zod-validated search params.

## Technical Approach

### Architecture

**Before (React Router):**
```
main.tsx: <RouterProvider router={router} />
  router.tsx: createBrowserRouter([...])
    Auth0ProviderWithNavigate (route element, uses useNavigate)
      ProtectedRoute (component guard, uses useAuth0 + useLocation)
        AppLayout (Outlet)
          React.lazy() + SuspenseWrapper per page
```

**After (TanStack Router):**
```
main.tsx: <Auth0Provider> → <InnerApp /> → <RouterProvider router={router} context={{ auth }} />
  routeTree.gen.ts (auto-generated by Vite plugin)
    __root.tsx (AuthBridge + error boundary + pendingComponent)
      _authenticated.tsx (beforeLoad guard via context.auth)
        _layout.tsx (AppLayout with Outlet)
          Auto code-split route files
      login.tsx, callback.tsx, access-denied.tsx (public)
      $.tsx (404 catch-all)
```

### Critical Design Decisions

#### 1. Auth0 + beforeLoad Integration (resolves SpecFlow Q1, Q2, Q7)

The core challenge: `beforeLoad` can't call React hooks, but Auth0 exposes auth state via `useAuth0()`. Solution follows TanStack Router's official authenticated-routes pattern:

```tsx
// main.tsx
import { Auth0Provider, useAuth0 } from '@auth0/auth0-react'
import { RouterProvider, createRouter } from '@tanstack/react-router'
import { routeTree } from './routeTree.gen'

const router = createRouter({
  routeTree,
  defaultPreload: 'intent',
  scrollRestoration: true,
  defaultPendingComponent: LoadingScreen,
  context: { auth: undefined! },  // Set by InnerApp
})

// Type-safe router registration
declare module '@tanstack/react-router' {
  interface Register { router: typeof router }
}

// Bridge: passes Auth0 state as router context on every render
function InnerApp() {
  const auth = useAuth0()
  return <RouterProvider router={router} context={{ auth }} />
}

// Auth0Provider wraps everything — no router dependency
function App() {
  return (
    <Auth0Provider
      domain={import.meta.env.VITE_AUTH0_DOMAIN}
      clientId={import.meta.env.VITE_AUTH0_CLIENT_ID}
      authorizationParams={{
        redirect_uri: window.location.origin + '/callback',
        audience: import.meta.env.VITE_AUTH0_AUDIENCE,
      }}
      cacheLocation="memory"
      useRefreshTokens={true}
      useRefreshTokensFallback={true}
      onRedirectCallback={(appState) => {
        // router.navigate() — no useNavigate() needed
        const returnTo = appState?.returnTo
        const safePath = returnTo && returnTo.startsWith('/') && !returnTo.startsWith('//')
          ? returnTo : '/'
        router.navigate({ to: safePath })
      }}
    >
      <InnerApp />
    </Auth0Provider>
  )
}
```

**How it works:**
- `InnerApp` reads `useAuth0()` and passes as router context on every render
- When Auth0 finishes loading → `isAuthenticated` changes → `InnerApp` re-renders → fresh context flows to router
- `beforeLoad` accesses `context.auth.isAuthenticated` and `context.auth.isLoading`
- `onRedirectCallback` uses `router.navigate()` directly (module-scoped, no hooks needed)

#### 2. Auth Guard in _authenticated.tsx (resolves SpecFlow Q1, Q3, Q14)

```tsx
// routes/_authenticated.tsx
export const Route = createFileRoute('/_authenticated')({
  beforeLoad: ({ context, location }) => {
    // While Auth0 SDK is initializing, don't redirect — let component show loading
    if (context.auth.isLoading) return

    // Auth0 done loading, user not authenticated → redirect to login
    if (!context.auth.isAuthenticated) {
      throw redirect({
        to: '/login',
        search: { returnTo: location.href },
      })
    }
  },
  component: AuthenticatedLayout,
})

function AuthenticatedLayout() {
  const { auth } = Route.useRouteContext()
  const authStatus = useAppStore((s) => s.auth.status)

  // Auth0 still loading, or backend sync in progress
  if (auth.isLoading || authStatus === 'authenticating' || authStatus === 'switching') {
    return <LoadingScreen />
  }

  return <Outlet />
}
```

**Key:** `beforeLoad` handles the "definitely not authenticated" redirect. The component handles loading/transitional states. This is the hybrid approach — `beforeLoad` for the fast redirect, component for the loading UX.

#### 3. returnTo via Search Params (resolves SpecFlow Q3)

```tsx
// routes/login.tsx
const loginSearchSchema = z.object({
  returnTo: z.string().optional(),
})

export const Route = createFileRoute('/login')({
  validateSearch: zodValidator(loginSearchSchema),
  component: LoginPage,
})

function LoginPage() {
  const { returnTo } = Route.useSearch()
  const { loginWithRedirect } = useAuth0()

  useEffect(() => {
    loginWithRedirect({ appState: { returnTo: returnTo || '/' } })
  }, [])

  return <LoadingScreen />
}
```

The chain: `beforeLoad` redirect → `/login?returnTo=%2Fcampaigns` → Auth0 `appState` → `onRedirectCallback` → `router.navigate({ to: returnTo })`. URL validation in `onRedirectCallback` prevents open redirect attacks.

#### 4. useAuthInit Refactored (resolves SpecFlow Q6)

Strip redirect logic from `useAuthInit` — `beforeLoad` handles that now. Keep only the data-loading part:

- POST `/users/login` (sync user with backend)
- GET `/users/me` + `/accounts/configs` (parallel)
- Update Zustand store → `authenticated`

The hook is called from the `_authenticated` layout component. AbortController cleanup for Strict Mode is preserved.

#### 5. useAccountSwitch Migration (resolves SpecFlow Q14)

Replace `useNavigate()` with the exported `router` instance:

```tsx
// After successful account switch
router.navigate({ to: '/' })
```

Or use `useNavigate()` from `@tanstack/react-router` — same API name, different package.

#### 6. AuthBridge Placement (resolves SpecFlow Q3b)

`AuthBridge` moves to the `__root.tsx` component. It renders inside Auth0Provider context (since Auth0Provider wraps the entire app) and sets the token fetcher on the API client:

```tsx
// routes/__root.tsx
function RootComponent() {
  return (
    <>
      <AuthBridge />
      <Outlet />
      <Toaster />
    </>
  )
}
```

#### 7. Sidebar Link Active State (resolves SpecFlow Q13)

Replace `NavLink` + manual `startsWith` with TanStack Router's `Link` + `activeProps`:

```tsx
<Link
  to={item.route}
  activeProps={{ className: 'bg-sidebar-accent text-sidebar-accent-foreground' }}
  activeOptions={{ exact: false }}  // matches startsWith behavior
  className="text-sidebar-muted hover:bg-sidebar-accent/50"
/>
```

#### 8. Placeholder Route Files (resolves SpecFlow Q4)

Each placeholder is a 5-line file importing the shared `Placeholder` component:

```tsx
// routes/_authenticated/_layout/campaigns.tsx
import { createFileRoute } from '@tanstack/react-router'
import { Placeholder } from '@/components/placeholder'

export const Route = createFileRoute('/_authenticated/_layout/campaigns')({
  component: Placeholder,
})
```

30 files, but each is trivial and will be replaced with real pages in upcoming phases.

#### 9. 404 Catch-All (resolves SpecFlow Q8)

Place `$.tsx` at the root level (outside `_authenticated`) so unauthenticated users see a 404 page instead of being redirected to login:

```tsx
// routes/$.tsx
export const Route = createFileRoute('/$')({
  component: NotFoundPage,
})
```

#### 10. Error Boundaries (resolves SpecFlow Q9)

Add `errorComponent` to `__root.tsx` for global error catching:

```tsx
// routes/__root.tsx
export const Route = createRootRouteWithContext<RouterContext>()({
  component: RootComponent,
  pendingComponent: LoadingScreen,
  errorComponent: ({ error }) => (
    <div className="flex h-screen items-center justify-center">
      <p>Something went wrong: {error.message}</p>
      <Button onClick={() => router.navigate({ to: '/' })}>Go Home</Button>
    </div>
  ),
})
```

#### 11. Home Page Redirect (resolves SpecFlow Q10)

Keep as component-based redirect (not `beforeLoad`) since it depends on permission checks from Zustand:

```tsx
// routes/_authenticated/_layout/index.tsx
export const Route = createFileRoute('/_authenticated/_layout/')({
  component: HomePage,
})

function HomePage() {
  const { can } = usePermissions()
  const defaultRoute = DEFAULT_ROUTE_MAP.find((r) => can(r.permission))
  if (defaultRoute) return <Navigate to={defaultRoute.route} />
  return <div>Bem-vindo ao MsgOps</div>
}
```

Note: `Navigate` here is from `@tanstack/react-router`.

## System-Wide Impact

### Interaction Graph

1. **Auth flow (changed):** Browser → Auth0Provider → InnerApp (passes auth context) → RouterProvider → `_authenticated.tsx` beforeLoad checks `context.auth` → `AuthenticatedLayout` calls `useAuthInit()` → backend sync → store `authenticated` → `_layout.tsx` renders AppLayout → page
2. **Navigation (changed):** Sidebar `<Link>` (typed) → TanStack Router handles transition → `autoCodeSplitting` loads chunk → route component renders
3. **Account switch (minor change):** Same flow but `router.navigate({ to: '/' })` instead of `useNavigate()('/')`
4. **API calls (unchanged):** Axios interceptors, token caching, TanStack Query — no changes

### Error & Failure Propagation

| Error Source | Handling |
|---|---|
| Auth0 SDK init failure | `__root.tsx` `errorComponent` catches |
| Auth0 callback error | `routes/callback.tsx` component handles (same as before) |
| `beforeLoad` redirect | TanStack Router handles `redirect()` throw natively |
| Route chunk load failure | `errorComponent` on `__root.tsx` or route-level |
| API 401 during auth switch | Same: skip logout when `auth.status === 'switching'` |

### State Lifecycle Risks

- **`beforeLoad` + Auth0 loading race:** Mitigated by checking `isLoading` in `beforeLoad` — skips redirect during initialization
- **Strict Mode double-mount:** AbortController in `useAuthInit` preserved
- **Router context staleness:** `InnerApp` re-renders on every Auth0 state change, passing fresh context
- **`routeTree.gen.ts` drift:** Auto-generated by Vite plugin on file changes in dev; `build` script generates before bundling

## Risk Analysis & Mitigation

| Risk | Impact | Mitigation |
|---|---|---|
| `beforeLoad` fires before Auth0 loads | Users incorrectly redirected to login | Check `isLoading` in beforeLoad — skip redirect while loading |
| `routeTree.gen.ts` not regenerated | Routes 404 in dev | Vite plugin watches file changes; CI runs `build` which generates |
| TanStack Router Link API differs from NavLink | Broken sidebar active state | Use `activeProps` + `activeOptions={{ exact: false }}` |
| Test infrastructure rewrite | Tests break during migration | Write `renderWithRouter` utility first, migrate tests incrementally |
| `onRedirectCallback` timing | returnTo lost during Auth0 redirect | Validate with smoke test: visit `/campaigns` → login → land on `/campaigns` |
| File-based route naming mistakes | Wrong URL paths generated | Verify `routeTree.gen.ts` after creating each route file |
